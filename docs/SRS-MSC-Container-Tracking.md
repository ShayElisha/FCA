## 1. סקירת המערכת ומטרתה

### 1.1 רקע עסקי

חברות יבוא/לוגיסטיקה בישראל נדרשות לעקוב באופן שוטף אחר מכולות המשויכות להפלגות של MSC (Mediterranean Shipping Company), ולדעת מתי המכולה צפויה להגיע לנמלי ישראל — בעיקר **אשדוד** ו**חיפה**. כיום המעקב נעשה ידנית דרך אתר המעקב של MSC, תהליך שגוזל זמן וחשוף לטעויות.

### 1.2 מטרת המערכת

פיתוח רכיב אוטומטי (ובאופציה ממשק משתמש פשוט) אשר:

1. מקבל **מספר מכולה** (Container Number).
2. מבצע שאילתה מול מערכת המעקב של MSC.
3. מנתח את נתוני הסטטוס והמיקום.
4. מציג את **מועד ההגעה הצפוי (ETA)** לנמלי ישראל (אשדוד / חיפה).

### 1.3 יעדים עיקריים

| יעד | תיאור | מדד הצלחה |
|-----|--------|-----------|
| חיסכון בזמן | צמצום מעקב ידני באתר MSC | שאילתה בודדת < 30 שניות |
| דיוק | הצגת ETA העדכני ביותר מ-MSC | התאמה לנתונים באתר הרשמי |
| בהירות | הצגה ממוקדת ליעד ישראלי | זיהוי Ashdod / Haifa |
| אמינות | טיפול בשגיאות וחסימות | הודעות ברורות + Retry מבוקר |

### 1.4 משתמשים עיקריים (Personas)

| פרסונה | תפקיד | צורך מרכזי |
|---------|--------|------------|
| מתאם לוגיסטיקה | מעקב יומיומי אחר מכולות | בדיקה מהירה של ETA בודד |
| מנהל יבוא | מעקב מרובה | רשימת מכולות / CSV |
| מערכת חיצונית | אינטגרציה (ERP / WMS) | API פנימי להחזרת JSON |

## 2. היקף, הנחות ואילוצים

### 2.1 בתוך ההיקף (In Scope)

- אימות מספר מכולה לפי **ISO 6346**.
- שאילתת מעקב מול MSC (API רשמי אם זמין; אחרת אוטומציה/חילוץ מבוקר).
- חילוץ: סטטוס, מיקום, אונייה/הפלגה, נמל יעד, ETA.
- סינון והצגת יעד ישראלי (אשדוד / חיפה).
- ממשק הזנה פשוט + תוצאה ויזואלית (אופציונלי).
- תמיכה בשאילתה בודדת; בשלב מתקדם — רשימה / CSV.
- טיפול בשגיאות, Throttle, ולוגים.

### 2.2 מחוץ להיקף (Out of Scope) — v1

- מעקב אחר חברות ספנות נוספות (Maersk, CMA CGM וכו').
- חישוב ETA עצמאי (מודל חיזוי) — המערכת מציגה את ה-ETA של MSC בלבד.
- ניהול משתמשים מלא / SSO / הרשאות ארגוניות מורכבות.
- התראות Push/SMS (ניתן בשלב 2).
- אחסון היסטורי ארוך-טווח לצורכי BI (אופציונלי בשלב 2).

### 2.3 הנחות

- מספר המכולה תקין לפי ISO 6346 וקיים במערכת MSC.
- נמל היעד הרלוונטי הוא בישראל (או שניתן לזהות קטע ישראלי במסלול).
- מקור האמת לנתונים הוא מערכת המעקב של MSC.
- השימוש מיועד לצורכי מעקב עסקי לגיטימי אחר מכולות השייכות לארגון.

### 2.4 אילוצים

| סוג | אילוץ |
|-----|--------|
| טכני | תלות במבנה/זמינות של אתר או API של MSC |
| תפעולי | Rate limiting — אין להציף את שרתי MSC |
| משפטי | יש לבדוק את תנאי השימוש (ToS) של MSC לפני Scraping; עדיפות ל-API רשמי / שותפות |
| סביבתי | פיתוח לשימוש מקומי (localhost) ו/או תהליך אוטומטי מתוזמן |

### 2.5 עדיפות מקור נתונים (סדר מומלץ)

1. **API רשמי של MSC** / שותף מסחרי (אם קיים וזמין לארגון).
2. **Endpoint פנימי מוסכם** שנחשף כחלק מממשק המעקב הציבורי (בקשות HTTP מתועדות, ללא עקיפת אבטחה).
3. **אוטומציית דפדפן** (Playwright/Puppeteer) כשכבת נפילה — רק לשימוש פנימי מבוקר, עם Throttle, ובהתאם ל-ToS.

> **הערה תכנונית:** מסמך זה מתאר דרישות מערכת. מימוש שכבת השליפה חייב לכבד את תנאי השימוש של MSC ואת החוק החל. אין להטמיע מנגנוני עקיפת הגנות (CAPTCHA / Cloudflare) כאסטרטגיה ראשית; יש לתעד סיכון ולשקול רישוי/API מסחרי.

## 3. ארכיטקטורה וטכנולוגיה מומלצת

### 3.1 תרשים רכיבים (לוגי)

```
┌─────────────────┐     HTTP/JSON      ┌──────────────────────┐
│  Frontend       │ ─────────────────► │  Backend API         │
│  React 18/Vite  │ ◄───────────────── │  Node/TS או FastAPI  │
│  (אופציונלי)    │                    └──────────┬───────────┘
└─────────────────┘                               │
                                                  ▼
                                       ┌──────────────────────┐
                                       │  Tracking Service    │
                                       │  ├─ Validator        │
                                       │  ├─ Provider Router  │
                                       │  ├─ MSC Client       │
                                       │  ├─ Parser/Normalizer│
                                       │  └─ Cache (אופציונלי)│
                                       └──────────┬───────────┘
                                                  │
                         ┌────────────────────────┼────────────────────────┐
                         ▼                        ▼                        ▼
              ┌─────────────────┐    ┌─────────────────┐     ┌─────────────────┐
              │ Official API    │    │ HTTP Endpoint   │     │ Browser Automa. │
              │ (מועדף)         │    │ (אם יציב)       │     │ Playwright      │
              └─────────────────┘    └─────────────────┘     └─────────────────┘
                                                  │
                                                  ▼
                                       ┌──────────────────────┐
                                       │  MSC Track Shipment  │
                                       │  msc.com/...         │
                                       └──────────────────────┘
```

### 3.2 המלצת Stack

| שכבה | אפשרות A (מומלצת) | אפשרות B |
|------|-------------------|----------|
| Backend | **Node.js + TypeScript + Express/Fastify** | Python + FastAPI |
| שליפה | Playwright (TypeScript) | Playwright / Requests (Python) |
| Frontend | React 18 + Vite + TypeScript | אותו דבר / CLI בלבד ב-v1 |
| Cache | Redis או קובץ/זיכרון מקומי (TTL) | SQLite |
| תצורה | `.env` + Zod/Pydantic | אותו עיקרון |
| לוגים | Pino / Winston | logging של Python |

### 3.3 עקרונות ארכיטקטוניים

1. **הפרדת שכבות:** Validation → Provider → Parser → Presenter.
2. **Provider Pattern:** אפשרות להחליף מקור נתונים (API ↔ HTTP ↔ Browser) בלי לשנות את ה-Frontend.
3. **Normalizer:** כל מקור מומר למודל אחיד `ContainerTrackingResult`.
4. **Fail soft:** כשל בשליפה מחזיר שגיאה מובנית, לא קריסת שרת.
5. **Idempotent queries:** אותה שאילתה בטווח TTL מחזירה תוצאה מ-Cache (אופציונלי).

## 4. תרשים זרימה (Workflow)

### 4.1 זרימה עיקרית

```
[משתמש מזין Container Number]
              │
              ▼
[Validation — ISO 6346]
              │
        ┌─────┴─────┐
        │ לא תקין   │──► הודעת שגיאה: מבנה מספר לא חוקי
        └─────┬─────┘
              │ תקין
              ▼
[Throttle / Queue — אם נדרש]
              │
              ▼
[בחירת Provider]
              │
              ▼
[שאילתה ל-MSC]
              │
        ┌─────┴──────────────────┐
        │ לא נמצא / Timeout     │──► הודעת שגיאה מתאימה
        │ חסימה / Rate limit    │──► Retry מושהה / הודעה
        └─────┬──────────────────┘
              │ הצלחה
              ▼
[Data Extraction + Normalizer]
  • Origin / Destination
  • Status / Location
  • Vessel / Voyage
  • ETA
              │
              ▼
[סינון יעד ישראלי]
  Ashdod / Haifa / אחר
              │
              ▼
[הצגת כרטיס תוצאה למשתמש / JSON ל-API]
```

### 4.2 פירוט שלבים

| # | שלב | תיאור |
|---|-----|--------|
| 1 | הזנת נתונים | המשתמש מזין מספר מכולה (לדוגמה: `MSCU1234567`) |
| 2 | אימות תקינות | בדיקת מבנה ISO 6346: 4 אותיות + 7 ספרות + (אופציונלי) ספרת ביקורת |
| 3 | שליחת שאילתה | פנייה למקור המעקב של MSC |
| 4 | חילוץ נתונים | איסוף Origin, Destination, Status, ETA, Vessel/Voyage |
| 5 | עיבוד והצגה | סינון לישראל והצגה ברורה של ETA |

## 5. מפרט פונקציונלי

### 5.1 FR-01 — מסך הזנה (Input)

| מזהה | דרישה | עדיפות |
|------|--------|--------|
| FR-01.1 | שדה טקסט יחיד להזנת מספר מכולה | Must |
| FR-01.2 | כפתור **"בדוק סטטוס"** (Search) | Must |
| FR-01.3 | נירמול קלט: Trim, Uppercase, הסרת רווחים/מקפים | Must |
| FR-01.4 | הצגת שגיאת ולידציה מיידית לפני שליחה | Must |
| FR-01.5 | תמיכה ברשימת מכולות (שורה אחר שורה) | Should (v1.1) |
| FR-01.6 | העלאת קובץ CSV למעקב מרובה | Could (v2) |
| FR-01.7 | מצב CLI / API ללא UI | Should |

**חוויית משתמש (Input):**

- Placeholder לדוגמה: `MSCU1234567`
- הודעת עזרה קצרה על פורמט ISO 6346
- מצב Loading בזמן השאילתה (Disable כפתור)

### 5.2 FR-02 — מודול אימות ISO 6346

| מזהה | דרישה | עדיפות |
|------|--------|--------|
| FR-02.1 | מבנה: `AAAA#######` (4 אותיות owner code + category, 7 ספרות) | Must |
| FR-02.2 | אות קטגוריה (מיקום 4) אחת מ: `U`, `J`, `Z` (מכולות רגילות לרוב `U`) | Should |
| FR-02.3 | בדיקת ספרת ביקורת (Check Digit) לפי אלגוריתם ISO 6346 | Should |
| FR-02.4 | דחיית קלט שאינו עומד בכללי המבנה לפני פנייה ל-MSC | Must |

### 5.3 FR-03 — מודול השליפה (Scraper / Parser / Client)

| מזהה | דרישה | עדיפות |
|------|--------|--------|
| FR-03.1 | שליפת נתוני מעקב עבור מספר מכולה תקין | Must |
| FR-03.2 | תמיכה ב-Provider הניתן להחלפה (API / HTTP / Browser) | Must |
| FR-03.3 | חילוץ שדות מפתח: ETA, Status/Location, Vessel/Voyage, Destination | Must |
| FR-03.4 | Timeout מוגדר לשאילתה (ברירת מחדל מומלצת: 45–60 שנ') | Must |
| FR-03.5 | Retry מוגבל (למשל 2 ניסיונות) עם Backoff | Should |
| FR-03.6 | סלקטורים גמישים / אסטרטגיות חילוץ מרובות (CSS / טקסט / JSON) | Should |
| FR-03.7 | זיהוי מצבי חסימה / CAPTCHA והחזרת שגיאה מובנית (ללא ניסיון עקיפה אגרסיבי כברירת מחדל) | Must |
| FR-03.8 | לוג טכני של כשלים (ללא שמירת PII מיותר) | Should |

**שדות לחילוץ (מינימום):**

| שדה | תיאור |
|-----|--------|
| `containerNumber` | המספר שאומת |
| `status` | לדוגמה: In Transit, Discharged, Gate Out |
| `currentLocation` | מיקום/אירוע אחרון |
| `originPort` | נמל מוצא (אם זמין) |
| `destinationPort` | נמל יעד |
| `eta` | תאריך/שעה משוערים להגעה |
| `vesselName` | שם האונייה |
| `voyageNumber` | מספר/קוד הפלגה |
| `rawSource` | מזהה ה-Provider |
| `retrievedAt` | חותמת זמן השליפה |

### 5.4 FR-04 — עיבוד יעד ישראלי

| מזהה | דרישה | עדיפות |
|------|--------|--------|
| FR-04.1 | זיהוי נמלי ישראל: Ashdod / Haifa (כולל וריאציות איות) | Must |
| FR-04.2 | מיפוי שמות חלופיים (למשל `ILASH`, `Ashdod Port`, `Haifa`) | Should |
| FR-04.3 | אם היעד אינו ישראלי — הצגת היעד בפועל + אזהרה | Must |
| FR-04.4 | אם אין ETA — הצגת סטטוס ומסר "ETA לא זמין" | Must |

### 5.5 FR-05 — ממשק התוצאות (Output)

כרטיס מידע הכולל:

| שדה מוצג | מקור |
|----------|------|
| מספר מכולה | הקלט המאומת |
| אונייה וקו הפלגה | Vessel + Voyage |
| יעד סופי בישראל | Ashdod / Haifa (או "לא זוהה יעד ישראלי") |
| תאריך הגעה צפוי (ETA) | התאריך/שעה העדכניים ביותר מ-MSC |
| סטטוס נוכחי | Status / Location |
| זמן עדכון | `retrievedAt` |

| מזהה | דרישה | עדיפות |
|------|--------|--------|
| FR-05.1 | הצגת כרטיס תוצאה בעברית (תוויות) עם נתונים מקוריים באנגלית לפי הצורך | Must |
| FR-05.2 | פורמט תאריך מקומי (Asia/Jerusalem) | Should |
| FR-05.3 | אפשרות להעתקת JSON / שיתוף תוצאה | Could |
| FR-05.4 | במעקב מרובה — טבלה עם סטטוס לכל מכולה | Should (v1.1) |

### 5.6 FR-06 — מעקב מרובה (Batch) — שלב מתקדם

| מזהה | דרישה | עדיפות |
|------|--------|--------|
| FR-06.1 | עיבוד רשימה עם תור פנימי ו-Throttle בין פריטים | Should |
| FR-06.2 | סיכום: N הצליחו / M נכשלו | Should |
| FR-06.3 | ייצוא תוצאות ל-CSV | Could |

## 6. מפרט לא-פונקציונלי

| מזהה | קטגוריה | דרישה |
|------|----------|--------|
| NFR-01 | ביצועים | שאילתה בודדת מוצלחת תוחזר תוך ≤ 30 שנ' בממוצע (תלוי ב-MSC) |
| NFR-02 | זמינות | Backend זמין לשימוש מקומי; טיפול ב-Timeout ללא תקיעת UI |
| NFR-03 | אמינות | כשל Provider לא מפיל את השרת; שגיאה מובנית ללקוח |
| NFR-04 | תחזוקתיות | סלקטורים/פרסרים מבודדים; בדיקות יחידה ל-Normalizer ול-Validator |
| NFR-05 | מדידות | לוגים לזמן תגובה, סוג שגיאה, Provider בשימוש |

## 9. טיפול בשגיאות

### 9.1 טבלת שגיאות למשתמש

| קוד | תרחיש | הודעה למשתמש (עברית) |
|-----|--------|----------------------|
| `INVALID_CONTAINER_NUMBER` | מבנה לא תקין | מספר המכולה אינו תקין לפי תקן ISO 6346. הפורמט הנדרש: 4 אותיות ו-7 ספרות. |
| `NOT_FOUND` | לא קיים ב-MSC | מספר מכולה לא נמצא במערכת MSC, נא לוודא את הנתונים. |
| `TIMEOUT` | זמן תגובה ארוך | לא התקבלה תשובה ממערכת MSC בזמן. נסו שוב בעוד מספר דקות. |
| `RATE_LIMITED` | הגבלת קצב | בוצעו יותר מדי בקשות בזמן קצר. המערכת ממתינה לפני ניסיון נוסף. |
| `SOURCE_BLOCKED` | חסימת גישה / אתגר אבטחה | הגישה למקור הנתונים של MSC נחסמה זמנית. נסו מאוחר יותר או השתמשו ב-API רשמי. |
| `PARSE_FAILED` | שינוי מבנה / כשל חילוץ | התקבלו נתונים אך לא ניתן היה לחלץ ETA/סטטוס. ייתכן שמבנה העמוד השתנה. |
| `PROVIDER_UNAVAILABLE` | ספק לא זמין | שירות השליפה אינו זמין כרגע. |
| `INTERNAL_ERROR` | תקלה כללית | אירעה תקלה פנימית. נסו שוב או פנו למנהל המערכת. |

### 9.2 Rate Limiting / Throttle

| כלל | המלצה |
|-----|--------|
| השהייה בין בקשות Batch | 5–10 שניות (ניתן להגדרה ב-`.env`) |
| מקסימום ניסיונות Retry | 2 |
| Backoff | אקספוננציאלי בסיסי (למשל 5s → 15s) |
| Cache TTL | 15–30 דקות לאותו מספר מכולה |

### 9.3 עמידות לשינויי DOM

אסטרטגיה בשכבות:

1. ניסיון חילוץ מ-JSON / תשובת רשת מובנית (אם קיימת ויציבה).
2. סלקטורים סמנטיים לפי תוויות טקסט (`ETA`, `Destination`, `Vessel`).
3. Fallback לסלקטורים חלופיים.
4. אם כל השכבות נכשלות → `PARSE_FAILED` + התראת תחזוקה בלוג.

אין להסתמך על סלקטור יחיד שביר (למשל class אקראי של CSS-in-JS).

## 12. קריטריוני קבלה

### AC-01 — שאילתה תקינה

**נתון:** מספר מכולה תקין שקיים ב-MSC ומגיע לאשדוד/חיפה.  
**תוצאה:** מוצגים מספר מכולה, סטטוס, יעד ישראלי, ETA (אם קיים), ואונייה/הפלגה (אם קיימים).

### AC-02 — מספר לא תקין

**נתון:** `123` או `MSC`.  
**תוצאה:** אין פנייה ל-MSC; מוצגת הודעת `INVALID_CONTAINER_NUMBER`.

### AC-03 — מספר לא קיים

**נתון:** מספר במבנה תקין שאינו קיים.  
**תוצאה:** הודעת `NOT_FOUND` בעברית כנדרש.

### AC-04 — יעד שאינו ישראלי

**נתון:** מכולה עם יעד שאינו Ashdod/Haifa.  
**תוצאה:** מוצג היעד המקורי + `israelPort = Unknown` + אזהרה.

### AC-05 — כשל מקור

**נתון:** Timeout / חסימה.  
**תוצאה:** הודעת שגיאה מתאימה; השרת נשאר פעיל.

### AC-06 — Batch throttle (v1.1)

**נתון:** 5 מכולות ברצף.  
**תוצאה:** הבקשות מרווחות לפי ההגדרה; אין הצפה מיידית של המקור.
